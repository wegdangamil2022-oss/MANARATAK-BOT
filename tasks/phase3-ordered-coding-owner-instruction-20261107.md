## ترتيب العمل

2. يبدأ العمل من القسم الأول «01. 👥 المجموعات والشبكات» ثم الزر الفرعي الأول «01-01. 📋 مجموعاتي»، ثم ينتقل إلى «01-02. ➕ ربط مجموعة»، وهكذا زرًا ثم قسمًا حسب ترتيب الخطة، مع فحص الشفرة والربط والصلاحيات أولًا، وعدم تكرار ما هو مكتمل.
3. تنفذ النواقص البرمجية على الفرع `feature/phase3-closure-review-20261103` المرتبط بطلب الدمج `#184`. لا تغيير على `main` أو على فرع المرحلة الرابعة `#186`، ولا دمج دون أمر واضح.
4. **لا تُشغّل اختبارات أو فحوص CI أو عروضًا تجريبية إطلاقًا** وفق قرار المالك الحالي. تستخدم رسالة `[skip ci]` مع كل Commit لتجنب تشغيل GitHub Actions بسبب الرفع. لا تذكر «نجحت الاختبارات» أو «أُغلق نهائيًا» عن كود لم يختبر بعد، ولا تغيّر معايير السلامة أو تخففها للتعويض.
5. لا تُنفذ أية عقوبات حقيقية، ولا نشر جماعي، ولا تغير إعدادات Telegram الإنتاجية. تبقى قيود إثبات التفويض، وإعادة فحص الصلاحيات، ووضع STOP، وعدم إعادة المحاولات الغامضة إلزامية.
6. يوثق كل زر: الموجود فعليًا، والنقص المحدد، والشفرة المضافة، وما يلزم لاحقًا، **بدون تشغيل اختبارات**. لا يُعد وجود زر في الكتالوج إثبات اكتمال الوظيفة.
