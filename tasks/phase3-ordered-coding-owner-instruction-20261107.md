هذه تعليمات عمل صريحة أحدث من أي أسلوب سابق يقضي بضرورة تشغيل الاختبارات مع كل دفعة؛ لا تُفهم على أنها دليل نجاح اختبارات أو اكتمال وظيفة.

## ترتيب العمل
1. تُستخدم **الخطة الرئيسية** `docs/MANARATAK_BOT_MASTER_v1.2.1_AR.md` مرجعًا للمتطلبات، و`docs/أزرار_منارتك.md` مرجعًا لترتيب الأقسام والأزرار المعتمدة.
2. يبدأ العمل من القسم الأول «01. 👥 المجموعات والشبكات» ثم الزر الفرعي الأول «01-01. 📋 مجموعاتي»، ثم ينتقل إلى «01-02. ➕ ربط مجموعة»، وهكذا زرًا ثم قسمًا حسب ترتيب الخطة، مع فحص الشفرة والربط والصلاحيات أولًا، وعدم تكرار ما هو مكتمل.
3. تنفذ النواقص البرمجية على الفرع `feature/phase3-closure-review-20261103` المرتبط بطلب الدمج `#184`. لا تغيير على `main` أو على فرع المرحلة الرابعة `#186`، ولا دمج دون أمر واضح.
4. **لا تُشغّل اختبارات أو فحوص CI أو عروضًا تجريبية إطلاقًا** وفق قرار المالك الحالي. تستخدم رسالة `[skip ci]` مع كل Commit لتجنب تشغيل GitHub Actions بسبب الرفع. لا تذكر «نجحت الاختبارات» أو «أُغلق نهائيًا» عن كود لم يختبر بعد، ولا تغيّر معايير السلامة أو تخففها للتعويض.
5. لا تُنفذ أية عقوبات حقيقية، ولا نشر جماعي، ولا تغير إعدادات Telegram الإنتاجية. تبقى قيود إثبات التفويض، وإعادة فحص الصلاحيات، ووضع STOP، وعدم إعادة المحاولات الغامضة إلزامية.
6. يوثق كل زر: الموجود فعليًا، والنقص المحدد، والشفرة المضافة، وما يلزم لاحقًا، **بدون تشغيل اختبارات**. لا يُعد وجود زر في الكتالوج إثبات اكتمال الوظيفة.

## نقطة العمل الحالية — القسم 01، الزر 01-01 «مجموعاتي»
- الموجود قبل التعديل: قائمة المجموعات المعتمدة محليًا مع صفحات وبطاقة المجموعة، وملخصات الحماية والاشتراك وبعض انتقالات الإعداد والتفويض. لا تُثبت البطاقة اسم المجموعة أو نوعها أو حقوق Telegram الحية أو اللغة والمنطقة الزمنية.
- أُضيف مسار قراءة معلومات محلية مستقل `mi:1:g:i:<chatId>:<version>:<page>` ضمن `telegram-inline-groups.ts`، مع زر من بطاقة المجموعة، وتوسيع مدقق أزرار `telegram-inline-owner.ts`. يعيد فحص المالك والاعتماد والنسخة وصفحة القائمة قبل الوصول، ولا يكتب بيانات أو يعامل العنوان غير المحفوظ دليلًا من Telegram.
- **ما لم يكتمل من هذا الزر:** الاسم والنوع من مصدر Telegram موثوق، وتصميم حفظ اللغة والتوقيت المراجَع، والتحقق الحي الخاص بكل مجموعة قبل عرض معلومات ديناميكية. لا يجوز وصف `01-01` بأنه مغلق أو مجرّب بعد.
- الخطوة البرمجية التالية هي استكمال هذه النواقص أو توثيق سبب تأجيل اعتماد المصدر الخارجي بوضوح قبل الانتقال إلى `01-02`؛ ولا يجوز التوجه إلى `NETWORK-006` أو `NETWORK-007` قبل الوصول إليهما في ترتيب الأزرار.

**حالة الفحص:** فحص شفرة استاتيكي ورفع GitHub فقط؛ لا اختبارات شُغلت بناءً على هذا التوجيه.
