# استكمال المرحلة الثالثة ثم الانتقال للرابعة

المرجع: جدول التنفيذ المعتمد في MANARATAK_BOT_MASTER_v1.2.1_AR.md، ثم المتطلبات التفصيلية وسجل MASTER_REQUIREMENTS_1_4.json. تأجيل Telegram الحقيقي قرار المستخدم، وليس قبول تشغيل حي.

1. أُنجز حفظ التنفيذ المحلي المتراكم في فرع مراجعة مستقل عن main وعن أساس المرحلة الثالثة 4b3a0550de4527341161ec02921b481196588549، دون ملفات التشغيل أو الأسرار أو قواعد البيانات؛ مسودة المراجعة #184.
2. أُنجز فحص Ubuntu للنسختين 18e328c و775e880، واجتازتا CI الكامل دون تخفيف شروط الأمان. تُحفظ إخفاقات Windows التاريخية مستقلة، وتظل أي تغييرات تنفيذية جديدة محتاجة إلى تحقق جديد.
3. مطابقة وظائف المرحلة الثالثة بالمتطلبات الرسمية: العقوبات والاستعادة، الإدارة والصلاحيات وغرف التحكم، الحماية والاستثناءات، الحذف والتنظيف، الاشتراك والقوانين. يجب أن يرتبط كل مطلب بدليل وظيفة وأزرار وفحص أو نقص صريح؛ الملفات وحدها ليست قبولًا.
4. إتمام النواقص المحلية المثبتة وإعادة اختبارات كل تغيير، ثم إصدار تقرير إغلاق محلي مستقل عن تجربة Telegram المؤجلة.
5. بعد اكتمال شروط الإغلاق المحلي، بدء المرحلة الرابعة من الخطة الرسمية: خدمات المجموعات والنشر والألعاب والتصويت، مع تتبع مستقل وعدم اعتبار وجود القوائم تنفيذًا لوظائفها.

لا تُعد هذه الخطة إغلاقًا لأي مرحلة. لا تُدمج تغييرات main ولا يُفعّل تشغيل Telegram أو تُعدل قاعدة أصلية بهذه الخطوات.
