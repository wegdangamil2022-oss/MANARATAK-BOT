# إنهاء سبب مستوفى مع حفظ القيد المستقل

كان رفع سبب من عدة أسباب عن عضو مقيّد يعطّل الإثبات اللاحق: البوابة تحمي الهدف restricted، ودليل الاستعادة يشترط تطابق بصمة جميع الأسباب مع إيصال العملية الأصلية. إزالة صف محلي مباشرة لا تثبت بقاء القيد ولا تحفظ سلسلة الإثبات.

أضيف المسار الداخلي `ModerationService.retireManualReasonPreservingRestriction`. يحتاج المالك وصلاحية اللوحة واعتماد المجموعة، وقرارًا حاليًا لا يتجاوز دقيقتين. يرفض وجود عملية معلقة أو غامضة، ويحتاج إيصال Telegram مؤكدًا وفريدًا وأحدث، مع نمط استعادة أذونات المجموعة الأصلي.

يقبل المسار إزالة سبب MANUAL واحد فقط حين يبقى سبب آخر وتبقى **العقوبة الفعلية ومدتها كما هما تمامًا**. تقرأ البوابة الرسمية حالة العضو وحقوق البوت مرارًا مع إعادة فحص المصدر المحلي؛ يجب أن يظل القيد مطابقًا، ولا تكفي حالة CLEAR. يرفض تغيّر الأذونات أو المدة أو المصدر أو الحقوق أو تفعيل STOP. لا يوسّع مسار setRestriction المعتاد ولا يرسل أمر فك قيد أو تعديل عقوبة.

يحفظ سجل تدقيق مستقل بصمة العملية الأصلية وبصمتي الأسباب قبل الإزالة وبعدها. يبقى إيصال العملية الأصلية دون تعديل، ولا تُضاف عملية CONFIRMED وهمية. يتحقق قارئ الإثبات من سلسلة فريدة، وإزالة سبب واحد في كل حلقة، وثبات العقوبة والمدة، وهوية المالك ونسخة الاعتماد والأوقات. لا يعتمد ترتيب مصفوفة التدقيق دليلًا زمنيًا، ويرفض الفروع والتكرار والنقص والتعديل. أصبحت الاستعادة الصريحة للسبب المتبقي، واستعادة الاشتراك المأذونة، وتسجيل انتهاء المدة قادرة على التحقق من هذه السلسلة.

تغطي الاختبارات كتمًا وحظرًا مستقلين، وقيد الاشتراك، وتسلسل إزالة سببين، والاستعادة اللاحقة وانتهاء المدة، والحالة الخارجية المخالفة، وتغيير الحقوق والمصدر، والعمليات المعلقة والغامضة، وفقدان الدليل، واستبدال قارئ البوابة، ومحاولات غير المالك. يجري كل ذلك على JSON وSQLite ببوابة API محاكية؛ اختبار Telegram الحقيقي ما زال مؤجلًا.

**حدود هذه الدفعة:** هذا أساس داخلي لاجتماع القيود؛ لم يوصل تلقائيًا بنجاح CAPTCHA بعد. تبقى الموافقة المستقلة على إنفاذ CAPTCHA وإنشاء سببه وإيصاله، وربط النجاح والتدرج والمؤقت والتنبيهات والاشتراك والقوانين، مفتوحة. ليس هذا إغلاق المرحلة الثالثة أو تفعيلًا لعقوبات Telegram الحية.
