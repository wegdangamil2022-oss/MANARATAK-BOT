# NETWORK-005 — مقارنة إعدادات مجموعات الشبكة (الشريحة الأولى)

**الفرع:** المرحلة الثالثة، طلب الدمج #184. **الحالة:** المقارنة المحلية للقراءة فقط. لا توجد استعادة سياسة محفوظة في هذه الشريحة ولا يعد هذا إغلاقًا لـ NETWORK-005 أو المرحلة الثالثة.

## المسار من لوحة المالك

«🌐 الشبكات والاتحادات ← بطاقة الشبكة ← 🧩 مقارنة إعدادات المجموعات» في خاص المالك فقط.

1. تعرض شاشة النظرة العامة عدد المجموعات المرتبطة، والارتباطات المعتمدة بإصداراتها الحالية، والارتباطات القديمة أو الملغاة، والسياسات غير الجاهزة.
2. «📑 اختيار مجموعة مرجعية» يعرض المجموعات بصفحات من ثمانية، مع حالة كل عضوية وسياسة. الارتباطات القديمة، والسجلات المكررة، والمجموعات غير المعتمدة لا يمكن اختيارها.
3. عند اختيار مجموعة مرجعية تظهر المجموعات المؤهلة للمقارنة، وتختار مجموعة ثانية من الشبكة نفسها فقط.
4. تُحسب المقارنة لحظة فتح الشاشة من الحالة الفعلية الحالية في JSON أو SQLite، دون تخزين نسخ مقارنة أو إنشاء إيصالات أو تعديل سياسة.

## ما الذي يُقارن؟

- وضع المساعد الذكي (`groupAI`) ونطاقات خدمات المجموعة.
- وضع الحماية `OFF / MONITOR / ENFORCE`، وقواعد الحماية وإعداداتها، والنطاقات والعبارات المسموحة.
- الاستثناءات الدائمة والمؤقتة واستثناءات القواعد.
- الفلود، وموجات الانضمام، والهجمات، ووضع الليل، والتصعيد.

تُستبعد من التماثل **هوية المجموعة وتاريخ وآخر محرر وإصدار سجل السياسة**؛ لذلك يمكن أن تكون سياستان متطابقتين وظيفيًا رغم اختلاف إصدارهما أو تاريخ تحريرهما. أما الفرق في النص الفعلي لأي قاعدة أو نطاق فيُكتشف حتى لو تساوى عدد العناصر.

**خصوصية:** تُظهر الشاشة أسماء الحقول المختلفة، وأعداد العناصر، وأوضاع الخدمات فقط؛ لا تعرض كلمات محظورة أو روابط أو عبارات حساسة أو معرّفات أعضاء مستثنين. لا يستعمل المحرك تعبير «متطابقة» إذا كانت إحدى السياسات مفقودة أو قديمة أو غير قابلة للثقة.

## نموذج الحماية

- يتطلب الحساب معرّف المالك الموثوق وميزة لوحة المالك `owner.dashboard`، ولا تقبل شاشة Telegram الأزرار خارج محادثة المالك الخاصة.
- يُعاد التحقق من اعتماد كل مجموعة وإصدار ربطها بالشبكة عند كل فتح، ومن عدم وجود اعتماد مكرر لنفس المجموعة.
- لا تنقل عضوية الشبكة أي تفويض. مجموعة خارج الشبكة، أو مجموعة مرتبطة بإصدار قديم، أو مرفوضة الاعتماد لا تصبح مصدرًا أو وجهة مقارنة.
- سياسة `MISSING` أو `STALE` تظهر بوضوح بوصفها مقارنة جزئية؛ سياسة `CORRUPT` أو `DUPLICATE` تمنع تفاصيل المقارنة، دون محاولة إصلاح البيانات أو استخدام أول سجل عشوائي.
- تظل شاشة القراءة متاحة عند إيقاف الطوارئ للشبكة لتمكين المالك من تشخيص الاختلافات دون رفع الإيقاف.
- جميع أزرار `nw:1:ch/cp/cs/ct` ضمن حد Telegram البالغ 64 بايت، ولا تحتوي نصوص القواعد أو أسرارًا.
- لا تستعمل هذه الشريحة `store.transaction` لتعديل السياسات أو استدعاء Telegram API، ولا تُرسل عقوبات أو إجراءات إنفاذ.

## التحقق

الملفات الرئيسية: `src/network-policy-diff.ts` و`src/telegram-network-differences.ts` و`tests/owner-network-policy-diff-inline.test.ts`.

الاختبارات على محركَي JSON وSQLite تغطي: تساوي السياسات رغم اختلاف الهوية والإصدار، اكتشاف تغيير نص قاعدة ونطاق مع بقاء العدد نفسه دون تسرب القيمة، غياب السياسة، العضوية القديمة أو الملغاة، تكرار السجلات أو فسادها، رفض الوصول غير المصرح به، عزل شبكتين، التشغيل تحت STOP، تحديث إصدار مجموعة بعد عرض الأزرار، واستمرار المقارنة بعد إعادة إنشاء المحرر، وتقسيم صفحات الشبكات الأكبر من ثماني مجموعات.

## حدود الشريحة التالية

**الاسترجاع إلى سياسة سابقة لم يُنفذ بعد.** لتحقيقه بأمان، يلزم أولًا سجل نسخ محلية محفوظة ومحدودة ومتوافقة مع مخطط قاعدة البيانات، وبصمة للمحتوى وإصدارات المجموعة، ومعاينة `diff` قبل أي تغيير، وتفويض مستقل لا يعيد `ENFORCE` أو العقوبات أو أذونات Telegram تلقائيًا. وجود شاشة مقارنة فقط لا يعني توفر تاريخ نسخ يمكن استرجاعه.
