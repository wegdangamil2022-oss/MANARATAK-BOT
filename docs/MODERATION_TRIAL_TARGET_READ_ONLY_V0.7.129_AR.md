# بوت منارتك v0.7.129 — فحص عضو تجربة الإشراف دون تنفيذ عقوبة

## ما الوظيفة الجديدة؟

تُتيح هذه الدفعة فحصًا استشاريًا **لعضو واحد محدد** قبل التفكير في تجربة الحظر والكتم داخل مجموعة Telegram معزولة. فحوص الإصدارات السابقة تحققت من حالة STOP، نسخة SQLite الاحتياطية، اعتماد مجموعة واحدة، وسلامة سجل العقوبات، ثم أجرت قراءتين لحقوق البوت. الجديد هو التحقق كذلك من **العضو المستهدف بالتجربة** مع إعادة فحص حقوق البوت أثناء تلك القراءات.

الفحص الجديد: `inspectIsolatedModerationTargetReadOnly` في `src/moderation-trial-target.ts`. وأضيف أمر التشغيل المحلي `npm run telegram:moderation-target -- ...`.

## خطوات التحقق

1. رفض مُعرّف عضو غير صحيح أو اختيار مالك البوت؛ هوية المالك `BOT_OWNER_ID` إلزامية ولا يغيّر ذلك قواعد حماية المالك في خدمات العقوبات.
2. تسجيل نقطة تحقق من الملفات الثلاثة: قاعدة بيانات SQLite التشغيلية، النسخة الاحتياطية، وملف STOP.
3. تشغيل فاحص النطاق المحلي المعزول وفاحص صلاحيات البوت الرسمي؛ لا يمكن البدء بقراءة العضو ما لم يُثبت وجود STOP ونسخة احتياطية مطابقة وصلاحية `can_restrict_members` مستقرة في قراءتين.
4. قراءة حالة العضو في Telegram باستدعاء `getChatMember`: يُعد صالحًا للفحص الاستشاري فقط إذا أعاد Telegram `member` لحساب بشري عادي بنفس المعرّف؛ يُمنع المشرفون والمالك والبوتات والحسابات المقيدة والمعلومات المجهولة.
5. إعادة فحص STOP والنطاق والملفات، وإعادة قراءة حق البوت بعد قراءة العضو الأولى؛ إذا سُحبت الصلاحية، يتوقف الفحص قبل قراءة ثانية للعضو.
6. قراءة ثانية لحالة العضو، ثم إعادة فحص الملفات وحق البوت؛ إذا اختلفت النتيجتان فالحالة `CHANGED` وقرار النطاق `BLOCKED`.
7. جميع النتائج ملخصات عامة فقط؛ لا يحتوي التقرير على رمز Telegram أو معرف العضو أو المجموعة أو المسارات الخاصة.

تُعيد الدالة `PASS` فقط إذا بقيت الأدلة المحلية والحقوق وحالة العضو سليمة عبر جميع نقاط القراءة. **PASS هنا لا يأذن بالحظر أو الكتم، ولا يرفع STOP، ولا يضمن أن العضو سيظل في هذه الحالة بعد الفحص**. تبقى العقوبات الحية غير موصولة بالخادم.

## تشغيل الأمر

في بيئة اختبار محلية تحتوي مسبقًا على ملفات SQLite ونسختها الاحتياطية وملف `STOP\n` الخاص، جهّز متغيرَي البيئة `TELEGRAM_BOT_TOKEN` و`BOT_OWNER_ID` عبر وسيلة إدارة أسرار موثوقة، وليس ضمن سطر الأوامر أو مستودع GitHub. لا تُدرج التوكن في لقطات شاشة أو سجلات.

```bash
npm run telegram:moderation-target -- \
  --offline-only \
  --state /private/trial/state.sqlite \
  --backup /private/trial/rollback.sqlite \
  --safety /private/trial/telegram.stop \
  --stale-ms 900000 \
  --trial-chat -1001234567890 \
  --trial-target 300123456
```

*المعرّفات والمسارات في المثال افتراضية وليست مجموعة حقيقية.*

إذا اكتملت القراءة يظهر تقرير JSON مختصر. رمز الخروج `0` يعني `PASS` **استشاريًا فقط**، ورمز `2` يعني `BLOCKED`، ورمز `1` يعني خطأ إعداد أو تشغيل دون طباعة معلومات حساسة. جميع اتصالات Bot API الخاصة بهذا الأمر من نوع `getChatMember` (قراءة الحالة)؛ لا يستدعي `banChatMember` أو `restrictChatMember`.

## حدود السلامة

- لا يجوز تشغيل فحص على مجموعة إنتاجية بغرض منحها صلاحية تجربة حية. يجب موافقة المالك واختيار مجموعة تجريبية مستقلة، وعضو اختبار موافق، وتوثيق خطة التراجع.
- نجاح الاختبارات الآلية على `fetch` وهمي لا يؤكد حالة Telegram الفعلية؛ الأمر يتصل بالمنصة فقط عند تشغيله عمدًا ببيانات اعتماد صحيحة.
- يجوز تغير حالة Telegram بعد الفحص مباشرة. لذلك لا تُستخدم النتيجة كتذكرة تنفيذ أو كبديل لفحوص آخر لحظة داخل بوابة عقوبات Telegram.
- التحقق من ملف STOP لا يرفعه ولا يعدل قاعدة البيانات أو النسخ الاحتياطية. يمكن تشغيل الفحص وملف `STOP` قائمًا كما هو.
