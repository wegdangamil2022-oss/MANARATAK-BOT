# استعادة عضو بقرار المالك — نطاق محلي منفصل

أضيف مسار خاص لتأكيد المالك فقط، ضمن معاينة unban/unmute الموجودة. لا يفعله أمر direct أو tick انتهاء أو أداة المراقبة. يبقى `setRestriction(NONE)` محجوبًا، وتبقى `ModerationReversalPreflight` للقراءة فقط ونتيجتها OBSERVED_NOT_ATTRIBUTABLE ليست صلاحية إرسال.

يشترط المسار سببًا يدويًا نشطًا واحدًا مطابقًا للمرجع والنوع، وأحدث عملية مؤكدة منفردة من المحول الرسمي لنفس الهدف ونسخة اعتماد المجموعة، مع تطابق بصمة الأسباب. العمليات الجديدة للمحول الرسمي تحمل baselineMode=INHERIT_GROUP_DEFAULTS؛ وهو تسجيل محلي لشرط المحول الذي لا يرسل BAN/MUTE إلا إلى عضو بشري عادي غير مقيد عند فحصه الأخير. ليس توقيعًا رقميًا ولا دليلًا من Telegram على مؤلف أي قيد لاحق. السجلات القديمة دون هذا الشرط، والمحاكاة، وتساوي التوقيت، والنتيجة المجهولة، والأسباب المحلية المستقلة، وتغير الاعتماد أو الصلاحيات تبقى محجوبة.

التأكيد الخاص يوضح للمالك أن تطابق الحالة لا يثبت عدم تدخل مشرف آخر، وأن ضغط التأكيد قرار استعادة يدوي بعد مراجعة ذلك. لا يستطيع Bot API إثبات صاحب قيد مطابق مستقل، ولا توجد مقارنة وتبديل ذرية بين القراءة والكتابة؛ لذلك لا يُقدَّم هذا المسار كاستعادة تلقائية أو ضمان ضد تدخل خارجي متزامن مماثل. تظل هذه مخاطرة مراجعة بشرية معلنة، ويُرفض أي اختلاف ظاهر في النوع أو المدة أو الأذونات.

قبل الإرسال يراجع المحول هوية المجموعة الفائقة والعضو وحقوق البوت وSTOP ومهلة القرار وشاهد السجل. الكتم القائم يجب أن يطابق جميع أذونات المنع المعروفة وموعده السابق؛ الحظر يجب أن يطابق موعده السابق. تغير الهدف إلى مشرف أو بوت أو قيد مختلف يمنع الإرسال. تعويض مصدر أو مرجع المحاولة أو دالة المحول يبطل الدليل ويحجر المحاولة عند اللزوم.

فك الحظر يرسل only_if_banned=true كي لا يطرد عضوًا عاد بالفعل. فك الكتم يستخدم صيغة البروتوكول التي تعيد العضو العادي إلى وراثة أذونات المجموعة العامة، وليس تغيير أذونات المجموعة أو استعادة مستخدم كان يملك قيودًا فردية مخصصة. يُشترط أن يؤكد الفحص اللاحق حالة member للكتم أو left/member للحظر. لا يكفي رد true. لا يعيد رفع الحظر العضو إلى المجموعة تلقائيًا.

يبقى السبب المحلي نشطًا طوال المحاولة؛ تتضمن بصمة INTENT الحالة المخطط لها بعد إزالة السبب، ويرتبط سجل NONE بمرجع reverses للعملية الأصلية. لا يتوقف السبب إلا داخل معاملة نجاح الفحص اللاحق. الرفض المؤكد يحفظ السبب ليتيح مراجعة جديدة؛ الغموض يحفظه ويحجر أي إعادة تلقائية. تغيّر قيد محلي آخر أثناء الانتظار يحجب التنفيذ ويحفظ جميع الأسباب.

تربط بصمات المحاولة والمراجعة والسجل وواجهات المعلق/المجهول حقلي baselineMode وreverses، مع بقاء بصمات السجلات القديمة دون الحقول متوافقة. اختبارات JSON وSQLite بنقل HTTP وهمي تغطي الحظر والكتم، والتأكيد الخاص لمرة واحدة، ورفض المشرف المفوض والنسخة القديمة والقيد المستقل واختلاف الأذونات والمدة، وSTOP/الحقوق، وتغير المصدر أو الإيصال، وفقد الرد وفشل الفحص اللاحق، وحفظ السبب عند التعارض ثم اشتراط مراجعة بشرية جديدة للتعافي. لا تجربة Telegram حية أو ربط بخادم التشغيل في هذه الشريحة.

مرجع البروتوكول: [unbanChatMember](https://core.telegram.org/bots/api#unbanchatmember) و[restrictChatMember](https://core.telegram.org/bots/api#restrictchatmember).
