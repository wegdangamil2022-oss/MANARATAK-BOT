# NETWORK-003 — فحص عقوبات الشبكة للقراءة فقط

**الحالة:** محرك فحص معلوماتي للقراءة فقط، مع واجهة مالك مشروطة تتصل ببوابة Telegram الرسمية بعد معاينة وموافقة مستقلة. لا ينفذ البوت عقوبات عبر هذه الواجهة ولا يتيح نقلها تلقائيًا.

## الخطوات

1. يجب أن تكون هناك مراجعة مستقلة لمجموعة مستهدفة واحدة في حالة `REVIEWED_ONLY` وبلاغ مصدر معتمد `WATCHED`، ضمن شبكة ومجموعتين معتمدتين بإصدارات ربط حديثة.
2. يفحص `inspectNetworkTransferLocal` الصلاحيات الحالية وحماية المالك والمشرفين، وعدم وجود أسباب إشراف نشطة أو محاولات معلقة أو مجهولة النتيجة، وسلامة سجل العقوبات. يظهر التقييم من زر «فحص الجاهزية المحلية» دون أي اتصال خارج البوت.
3. يمكن لمحرك `NetworkTransferReadOnlyPreflight` المنفصل عند حقنه بمحوّل Telegram الرسمي الموثوق أن يقرأ نوع **مجموعة المصدر والوجهة** وحقوق البوت وحالة العضو فيهما باستخدام `getChat` و`getChatMember` فقط. يجب أن يظهر في المصدر كتم أو حظر فعلي يوافق نوع المقترح، وفي الوجهة عضو عادي غير مقيد.
4. يفحص المحرك البيانات المحلية من جديد بعد كل انتظار، ويعيد رصد المصدر والوجهة مرتين؛ تغيّر الإصدارات أو الحقوق أو حالة المستخدم أو نوع المحادثة يؤدي إلى المنع. يرفض محولات القراءة المزيفة أو المعدلة أو أي نتيجة غير معروفة.
5. نجاح جميع القراءات يعطي `OBSERVED_ONLY` **ملاحظة لحظية، لا تصريحًا بنقل العقوبة**. لا تثبت قراءات Telegram هوية المسؤول الذي فرض العقوبة، ولا تعطي ضمانًا بأن الحقوق لم تتغير بعد انتهاء القراءة. لا يستخدم هذا المسار `setRestriction` أو أي عمليات إرسال أو تعديل قاعدة البيانات.

## اختبارات وضوابط

- `tests/owner-network-transfer-readonly-preflight.test.ts` يفحص العزل لكل وجهة باستخدام JSON/SQLite؛ رفض المراجعة غير المعتمدة، ورفض مصدر بلا عقوبة أو وجهة مقيّدة، والمنع عند تراجع صلاحيات المجموعة أثناء انتظار الشبكة، وانعدام أي أمر تعديل Telegram.
- `tests/owner-network-watchlist-inline.test.ts` يتحقق من زر الجاهزية المحلية، عزل المالك ومجموعات Telegram، وإظهار الأسباب دون عمليات إشراف جديدة.

**غير مفعّل:** نقل العقوبات أو تنفيذ أي حظر/كتم بسبب بلاغ شبكة، وأي نسخ أو إرسال عقوبات جماعية. تتطلب هذه الخطوات تفويضًا منفصلًا لكل مجموعة، وقيودًا تشغيلية واختبارات Telegram حية. لا تعد مشاهدة الفحص إذنًا بالعقاب.


## وضع شاشة المالك الحالية

أصبح زر «🔍 فحص الجاهزية المحلية» ظاهرًا في بطاقة اقتراح المجموعة بعد أن يعتمد المالك المراجعة بصيغة `REVIEWED_ONLY`؛ يستخدم `inspectNetworkTransferLocal` فقط. يعرض أسباب المنع مثل حماية العضو أو وجود عملية معلقة أو سبب إشراف قائم، أو يبين أن شروط القراءة المحلية مهيأة. **لا يستدعي زر الجاهزية المحلية محوّل Telegram الرسمي** ولا يقرر تنفيذ أي إجراء. ويوجد بجواره، في بيئة المرحلة الثالثة التي تملك البوابة الرسمية، زر منفصل للفحص الحي بعد موافقة المالك. مسارا الفحص محصوران بالقراءة ولا ينفذان عقوبات.


## تحديث 6 نوفمبر 2026 — ربط فحص Telegram المباشر بواجهة المالك

- بعد تسجيل مراجعة `REVIEWED_ONLY` مستقلة لمجموعة مستهدفة، تعرض بطاقة المقترح زر «📡 فحص Telegram (قراءة فقط)» **فقط حين يحقن المشغّل بوابة القراءة الرسمية للمرحلة الثالثة**. لا يظهر الزر في تشغيل المحاكاة دون البوابة.
- يُعيد البوت فحص الأهلية المحلية والمالك أولًا، ثم يعرض معاينة تتضمن المصدر والوجهة ومعرّف العضو. **المعاينة لا ترسل أي طلب Telegram**. يلزم تأكيد خاص أحادي الاستخدام قبل القراءة، صالح لدقيقتين، مع بصمة مرتبطة بإصدارات الشبكة والمجموعتين وحق الإدارة والسجلات المحلية.
- التأكيد يحجز إيصال القراءة قبل أول اتصال خارجي لمنع الضغط المكرر أو السباق. يُعيد فحص STOP قبل الاتصال وبعده، ويستخدم `NetworkTransferReadOnlyPreflight` لإجراء قراءات `getChat` و`getChatMember` الرسمية المتكررة، وتدقيق الاختلافات المحلية والبعيدة. رفض المصدر غير الموثوق أو فشل API أو زوال الصلاحية يعني نتيجة `BLOCKED`، لا إعطاء تصريح تنفيذ.
- إذا أظهر المصدر كتمًا/حظرًا مطابقًا والوجهة عضوًا عاديًا خلال قراءتين، تظهر رسالة **«رُصدت الحالة على Telegram»** بصفتها ملاحظة لحظية فقط، دون تغيير حالة مراجعة المجموعة أو سجل العقوبات. لا تُرسل `banChatMember` أو `restrictChatMember` أو أي إجراء تعديل.
- اختبارات التكامل في `tests/owner-network-sanction-remote-inline.test.ts` تعمل على JSON وSQLite، وتشمل موافقة المالك، غياب البوابة، إيقاف الأمان، تغيّر الشبكة والحقوق، الحالات المتعارضة، فقدان دليل المصدر، التزامن ومنع التكرار، وانقطاع الأمان أثناء الاتصال. **اختبار Telegram الحقيقي ما يزال مؤجلًا**، ولا يوجد نقل عقوبات تلقائي.
