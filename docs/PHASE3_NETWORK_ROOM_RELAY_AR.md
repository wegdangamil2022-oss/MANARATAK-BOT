# المرحلة الثالثة — NETWORK-006: توجيه مراجعات الشبكة إلى غرف الإدارة المعتمدة

**الحالة:** شفرة مضافة على فرع PR #184 فقط، دون تشغيل اختبارات أو بناء أو GitHub Actions وفق تعليمات المالك. **ليست نتيجة قبول Telegram حية**. لم تُدمج التعديلات في `main` ولم يُعدّل فرع المرحلة الرابعة #186.

## الهدف

عند وجود غرفة إدارة معتمدة مسبقًا للمجموعة بوضع `NOTIFICATIONS`، يظل ربط الغرفة مستقلًا عن عضوية الشبكة ولا يمنح صلاحية تلقائية لرسائل مراجعات الشبكة.

أضيفت طبقة ثالثة من الموافقة: **المالك وحده** يستطيع تفعيل أو إيقاف وصول تنبيهات *مراجعات الشبكة* إلى الغرفة المعتمدة، بشكل منفصل لكل مجموعة. لا تُفعَّل الميزة افتراضيًا، ولا يكفي ربط الغرفة الموجود أصلًا لإرسال الرسائل الجديدة.

## الدخول والتصفح

من «👥 المجموعات والشبكات ← 🌐 الشبكات والاتحادات ← بطاقة الشبكة»، يمكن استعمال:

```text
/networkrooms abcdef123456
/networkroomalerts abcdef123456
```

- `/networkrooms`: يفتح **لوحة حالة الربط السابقة للقراءة فقط**. أضيف فيها زر «🔔 مراجعة تفويض الإشعارات للغرف».
- `/networkroomalerts`: يفتح **إدارة الموافقة الجديدة** من خاص المالك فقط. يظهر لكل مجموعة مخوّل بإدارتها رقم غرفة تنبيهات ذات رابط معتمد ومستقل، ولا تُعرض الغرف التي لا يملك المالك إدارة طرفيها.
- يختار المالك مجموعة واحدة، ثم يراجع رقم الغرفة ونمط `NOTIFICATIONS` ونوع الأحداث، ويؤكد أو يلغي خلال دقيقتين ولمرة واحدة. لا يُرسل البوت أي رسالة خلال المعاينة أو الموافقة، ولا يتغير ربط الغرف الأصلي.

لا يُمكن تفعيل التوجيه عبر رابط `CONTROL` أو `CENTRAL` وحده، ولا تُستخدم عضوية الشبكة وسيلةً لتجاوز فحص إدارة المجموعة والغرفة. لا يغيّر مالك الشبكة موافقات غرف إدارة يملكها آخرون.

## ما الذي يمكن إرساله؟

فئتان فقط:

1. `WATCH_CASE`: تنبيه مختصر أن حالة بلاغ شبكة تغيرت للمراجعة البشرية.
2. `SANCTION_REVIEW`: تنبيه مختصر أن حالة مقترح إجراء إشرافي تغيرت للمراجعة البشرية.

الرسالة **نص ثابت** لا يقبل محتوى البلاغ أو رقم الطالب أو معرف المخالِف أو تفاصيل الأدلة أو كلمات الحماية أو زر تنفيذ عقوبة. وهي لا تثبت مخالفة ولا تنفذ حظرًا أو كتمًا ولا تضيف صلاحية للمراجعين. أحداث إيقاف الطوارئ العامة لا تنسب إلى مجموعة أو غرفة واحدة.

## حراس الموافقة والتسليم

- اشتراك تدقيقي مستقل `network:room:pref:<token>`، بنطاق شبكة واحدة ومجموعة واحدة وغرفة واحدة، مع بصمة تفويض المالك وبصمة رابط `NOTIFICATIONS` الأصلي وإصدارات اعتماد الشبكة والمجموعة والغرفة.
- جميع القرارات الحساسة من **خاص المالك** عبر المعاينة والتأكيد فقط. التراجع عن الاشتراك ممكن حتى لو كانت الغرفة في وضع الصمت أو الشبكة في حالة إيقاف طارئ، لأن الطوارئ تمنع **الإرسال** ولا تمنع سحب الموافقة.
- قبل أي محاولة، يتحقق عامل `NetworkRoomRelayDispatcher` من استمرار رابط الغرفة المستقل، وحقوق إدارة المالك للطرفين، وسلامة السجلات، وعدم الإيقاف الطارئ للشبكة، وعدم وضع الصمت الخاص بالغرفة، وأن الحدث حديث ومخوّل ومحدد بالمجموعة نفسها.
- يقرأ محول Telegram الرسمي وضع خصوصية الغرفة `inspectRoomPrivacy`، ولا يرسل إلا عندما يرد `NO_PUBLIC_USERNAME` من محول موثوق. يرفض القنوات والأنواع الغامضة والغرف العامة.
- قبل إرسال Telegram وبعد القراءة الرسمية يعاد فحص بوابة السلامة، وسلامة إيصال محاولة الإرسال، وصلاحية المصدر والوجهة ومحتوى الحالة الحالية للحدث. **أي تغير في ربط الغرفة أو صلاحيات المالك أو البيانات المرجعية يوقف الإرسال.**
- تحفظ محاولة الإرسال قبل الاتصال بمفتاح حتمي `network:room:send:<sha256>`، ويُسجل لاحقًا `CONFIRMED` أو `FAILED_CONFIRMED` أو `UNKNOWN_OUTCOME` أو `NOT_SENT`. النتيجة الملتبسة **لا يُعاد إرسالها**.
- لا يزيد العامل عن 3 محاولات افتراضيًا في الدورة، وبحد أقصى 8 عند الاستدعاء الموثوق، وبحد عام 60 رسالة جديدة بالدقيقة وحدّ أبرد للمالك مدته دقيقة. لا يحدث تشغيل خارج تفعيل المرحلة الثالثة ومؤقتاتها وبوابة الأمان الرسمية.

## الملفات

- `src/network-room-relay.ts`: حارس صلاحيات الربط وإيصالات الموافقة والإلغاء.
- `src/telegram-network-room-relay.ts`: قوائم المالك وقرارات التفعيل والإيقاف.
- `src/network-room-relay-dispatch.ts`: اختيار أحداث مراجعة جديدة وحجز محاولات التسليم وإعادة التحقق والنتائج.
- `src/admin-room-notices.ts`: مرسل Telegram رسمي بنص ثابت دون بيانات طلاب أو أزرار عقوبات.
- `src/telegram-inline-networks.ts` و`src/telegram-network-room-bridge.ts` و`src/telegram-transport.ts`: الربط مع شاشات الشبكات والغرف السابقة والأمر الخاص.
- `src/telegram-live-server.ts`: العامل الجديد تحت مفاتيح المرحلة الثالثة ومؤقتاتها.

## الحدود الواضحة

لا تشمل الميزة إرسال جميع أحداث الشبكات تلقائيًا، ولا تنقل صلاحيات المشرفين أو عقوبات الأعضاء. تعتمد على رابط `NOTIFICATIONS` حالي وصحيح وموافقة مالك مستقلة لكل مجموعة. تجربة التشغيل المباشر على Telegram وفحوص TypeScript وJSON وSQLite واختبارات التكامل **لم تُشغل** تنفيذًا لتعليمات المالك، ولذلك لا يجوز إعلان `NETWORK-006` أو `01-03` مغلقين تشغيليًا حتى إتمام المراجعات المتبقية.
