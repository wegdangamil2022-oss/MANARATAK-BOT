# NETWORK-006 — لوحة الأحداث الإدارية الموحدة (تصفية ومصادر موثقة)

## المسار المعتمد
«🌐 الشبكات والاتحادات ← الشبكة ← 🔔 الأحداث الإدارية للشبكة» في خاص المالك.

الشاشة للقراءة فقط. تجمع آخر الحالات المحلية المسجلة من أربعة مصادر:
1. بلاغات مراقبة الشبكة `NETWORK-003`، بحالتها الحالية ووقت تحديثها.
2. مقترحات العقوبات البشرية، دون اعتبار المراجعة إذنًا بالتنفيذ.
3. آخر قرار طوارئ محفوظ للشبكة `NETWORK-004`؛ لا يمثل تاريخ جميع الانتقالات.
4. عمليات حفظ النسخ التاريخية للسياسات `NETWORK-005` بعد التحقق من سلامة الأرشيف وبصمة النسخة، دون عرض القواعد أو محتوى السياسة أو مفتاح تجزئتها.

## التصفية والتنقل
- أزرار واضحة لاختيار «الكل، البلاغات، مراجعات العقوبات، الطوارئ، نسخ السياسات».
- اختيار مجموعة معتمدة حاليًا من صفحات قابلة للتنقل (8 مجموعات في الصفحة)، أو إعادة اختيار «كل المجموعات».
- حفظ نوع التصفية ومعرّف المجموعة في أزرار التنقل والعودة، مع التحقق من صلاحية كل زر ضمن حد Telegram البالغ 64 بايت. أزرار المسار القديم `nw:1:ev:<network>:<page>` ما زالت مدعومة.
- ترتيب الأحداث من الأحدث إلى الأقدم، ثمانية أحداث في الصفحة، حتى 200 حدث بعد تطبيق التصفية. إذا لم يوجد حدث يظهر وصف واضح بدل صفحة فارغة.
- الأحداث العامة للشبكة، مثل الطوارئ، لا تُنسب افتراضًا إلى مجموعة بعينها ولا تظهر في عرض المجموعة المحددة.

## الحماية والعزل
لا تعرض الشاشة هوية العضو أو النص المخالف أو تفاصيل البلاغ أو أسباب العقوبات أو قوائم الاستثناءات أو محتوى النسخ المحفوظة.

كل قراءة تتطلب مالك البوت ولوحة مالك مفعلة وشبكة فريدة سليمة. الأحداث المنسوبة إلى مجموعة لا تظهر إلا إذا كانت المجموعة حالياً معتمدة، وفي الإصدار نفسه الذي تتبعه الشبكة، وذات نطاق إشراف، وصلاحية `chat.manage` الحالية. مراجعات العقوبات تتطلب سلامة واعتماد **المصدر والهدف**، وتُرفض سجلاتها المكررة أو غير السليمة. لا يجوز تمرير معرّف مجموعة غير مرتبط أو لم تعد صالحة: في هذه الحال تفشل الشاشة دون إظهار نتائج المجموعة الكاملة.

النسخ التاريخية التي تَغيّر إصدار اعتماد مجموعاتها لا تُعرض ضمن هذه الشاشة، حتى إن بقيت محفوظة في الأرشيف؛ ولا تُقبل أي سجلات أرشيف تالفة أو متكررة. لا يُرسل أي تنبيه تلقائي، ولا تنشأ إيصالات موافقة، ولا يُعدّل أي سجل من مجرد التصفح.

## الاختبارات والحدود المتبقية
تغطي `owner-network-events-inline.test.ts` و`owner-network-events-filters-inline.test.ts` على JSON وSQLite: عزل الشبكات، الحماية من كشف هوية الطالب، المصادر الأربعة، أنواع التصفية والمجموعات، تبديل النوع والتنقل، استبعاد الأهداف التي فقدت الاعتماد، حجب الشاشة عند إغلاق لوحة المالك، ورفض الأزرار غير الصحيحة.

**ما يزال مفتوحًا:** الإرسال التلقائي للأحداث إلى مستلمين مرخّصين، قواعد إشعار كل مسؤول ومستوى صلاحيته، تفضيلات الصمت وحدود الضغط والتجميع، وتوسيع المصادر لتغطية أحداث أخرى بإيصالات تدقيق موثوقة. هذه اللوحة ليست نظام إشعارات مرسلًا، ولا تُعد إغلاقًا نهائيًا لـNETWORK-006 أو المرحلة الثالثة.

اختبار Telegram الحقيقي مؤجل، وPR #184 لا يُدمج في `main` ولا يغير PR #186.


## NETWORK-006 — الإشعارات الخاصة بالمشرفين (دفعة الاشتراك الاختياري)

**مسار المستلم:** يفتح المسؤول أو مالك البوت خاص البوت ويرسل `/networkalerts`. تعرض الشاشة فقط الشبكات التي تضم مجموعات معتمدة ذات صلاحية `chat.manage` حالية لهذا الشخص. لا يُضاف زر مستقل إلى القوائم الأساسية القديمة حتى لا يتغير تعاقدها مع أزرار Telegram؛ يبقى مدخل الاشتراك هو الأمر الخاص الموثق.

**الموافقة:** اختيار المجموعة ثم نوع الحدث من «🛡️ البلاغات»، «⚖️ مقترحات مراجعة العقوبات»، «📸 نسخ السياسات»، مع شاشة معاينة وتأكيد خاص لمرة واحدة صالح لدقيقتين. يمكن تعطيل كل نوع على حدة من الشاشة نفسها. يبدأ الجميع بحالة `OFF`. لا يستطيع المالك تشغيل التنبيهات نيابةً عن مشرف آخر؛ كل مستلم يؤكد بصفته الخاصة. لا تُرسل أحداث سُجلت قبل الموافقة.

**أذونات المستلم:** يلزم اعتماد المجموعة والإصدار الصحيح داخل الشبكة، ونطاق الاعتدال `moderation`، وحق `chat.manage` الخاص بالمستلم، وخدمة الدعم الخاصة، وعدم فقدان صلاحية لوحة المالك حين يكون المستلم مالكًا. تُربط الموافقة ببصمة تفويض المجموعة والشبكة؛ سحب الحق أو إلغاء اعتماد المجموعة أو تغيير إصدارها أو تغيير حقوق المستلم يبطل الموافقة القديمة ولا يحييها تلقائيًا. لا تصل أحداث المجموعات الأخرى إلى المشرف.

**المدقق وعامل التسليم:** يقرأ حالة الحدث من المخزون المعتمد نفسه الذي تستخدمه شاشة الأحداث، مع حد 120 ثانية لحدث حديث، وحد استلام رسالة واحدة لكل مسؤول خلال دقيقة و100 محاولة على مستوى البوت خلال الدقيقة. يُحفظ دليل `STARTED` ذريًا قبل إرسال طلب Telegram. لا إعادة لمحاولة تأخرت أو انقطعت نتيجة إرسالها أو لم يُثبت نجاحها. تعاد مراجعة الموافقة والحقوق والحدث ومحاولة الإرسال بعد بوابة السلامة وقبل النداء الخارجي، مع تسجيل `CONFIRMED` أو `FAILED_CONFIRMED` أو `UNKNOWN_OUTCOME` دون إرجاع تفاصيل حساسة. النص المُرسل عام، لا يحوي معرّف الطالب أو النص المخالف أو سياسة الحماية.

**التشغيل:** مقيّد بتفعيل المرحلة الثالثة ومؤقتاتها وبوابة سلامة الإرسال القائمة في `telegram-live-server.ts`. لا يفتح التنفيذ المحلي وحده Telegram أو يرسل رسالة من المحاكاة. لا يتيح أي حظر أو كتم أو فك عقوبة أو نقل جزاءات بين المجموعات.

**حدود هذه الدفعة:** ثلاث فئات فقط من الأحداث المقيدة بالمجموعة، ولا تُرسل إشعارات «طوارئ الشبكة» للمشرفين كحدث عام لأن صلاحية إدارة مجموعة لا تعني حق إدارة الشبكة كلها. ليس هذا اشتراكًا شاملاً بغرف الإدارة المشتركة، ولا يتيح جدولة ساعات الصمت وتلخيصات دورية. ربط الإشعارات بآليات أوسع للمالك والمراجعة الحية على Telegram لا يزال مطلوبًا قبل إغلاق `NETWORK-006` والمرحلة الثالثة.

**التغطية:** `tests/network-event-alerts.test.ts` لمحركي JSON وSQLite، وتظل جميع اختبارات الفرع وTypeScript والتدقيق والمحاكاة شروطًا ملزمة لكل تغيير.


## NETWORK-006 — الصمت المؤقت الشخصي للمستلمين

أُضيف داخل «🔔 إعداد إشعارات الشبكات ← المجموعة» تحكم منفصل لكل مسؤول ولكل مجموعة مؤهل لإدارتها:
- «🔕 صمت ساعة» و«🌙 صمت 8 ساعات» مع معاينة ذات هوية المجموعة والمدة وتأكيد خاص لمرة واحدة خلال دقيقتين.
- «🔔 إلغاء الصمت» عند وجود صمت فعّال، مع معاينة وتأكيد مستقلين. إلغاء الصمت لا يعيد إرسال الأحداث التي حدثت أثناءه.
- يعرض القسم وقت انتهاء الصمت بصيغة UTC صراحةً، دون افتراض منطقة زمنية للمستلم.
- كل تعديل يُسجل في إيصال تدقيق محلي ضمن JSON وSQLite؛ الوضع الافتراضي هو عدم الصمت ولا يُنشئ الاشتراك في أنواع أحداث جديدة.
- تتطلب المعاينة والتأكيد صلاحية `chat.manage` الحالية واعتماد المجموعة والشبكة والنطاق نفسه ودليل التفويض الحالي. تؤدي إزالة الصلاحية أو تغيّر الإصدار أو تكرار/تلف إيصالات التدقيق إلى المنع.
- يفحص عامل التسليم حالة الصمت ووقت الحدث قبل اختيار رسالة جديدة، ثم يعيد التحقق بعد بوابة السلامة وقبل إرسال Telegram. لا تُعاد طوابير الأحداث المكتومة عند انتهاء الصمت، ولا يُسمح بإشعارات مجموعات أخرى.

الاختبارات: `tests/network-event-silence.test.ts` على JSON وSQLite لسيناريوهات التفعيل والانتهاء والإلغاء والرفض عند سحب الحق والعبث بالإيصالات. كما يبقى معدل الإرسال الأساسي (رسالة واحدة لكل مستلم في الدقيقة) مطبقًا.

**الحدود:** الصمت مؤقت لمدة ساعة أو ثماني ساعات وفق طلب المستلم؛ لا يتضمن بعد جدول ساعات يومي متكرر حسب المنطقة الزمنية، ولا ملخصات دورية أو تحويل الإنذارات إلى غرفة الإدارة. تبقى تجربة Telegram الحية والقبول النهائي لـNETWORK-006 والمرحلة الثالثة مفتوحة.
