# المرحلة الأولى — جرد الواقع المحلي

تاريخ المراجعة: 29 أكتوبر 2026، توقيت الرياض. المرجع التنفيذي هو مقدمة الخطة المحدّثة في `MANARATAK_BOT_MASTER_v1.2.1_AR.md`، وليس ترتيب B0–B7 التاريخي.

هذه لقطة الجرد الأولى، وتبقى جداولها محفوظة بحسب sourceCommit في ملف JSON. التغييرات اللاحقة في [تنظيف الرسائل](PHASE3_REVIEWED_REPLY_DELETE_AR.md) رفعت عدد المداخل المرتبطة محليًا إلى 11. يعيد audit:phase1 حساب حالة الكود الحالية.

## نطاق الإغلاق

اكتمل الجرد والفحص المحلي للمرحلة الأولى. تجربة Telegram الحية مؤجلة بتعليمات المالك: لا توجد مجموعة تجريبية حاليًا، ويُجهز الكود والاختبارات محليًا أولًا. لذلك هذه **جاهزية جرد محلي** وليست إعلان جاهزية تشغيل أو قبول حي للمراحل التالية.

## النسخة والتشغيل

- الفرع المحلي: `fix/inline-owner-status-copy`؛ إصدار الحزمة `0.7.133`، والمخطط الدائم `schemaVersion: 8`.
- آخر `main` البعيد عند الفحص: `1954bed20c17f207c16b90e27799133787c96f84`. الفرع المحلي يتضمن أربعة إصلاحات سابقة موثقة في سجل Git؛ لا يفترض الجرد أنها منشورة.
- Node المحلي `24.19.0` وnpm `11.9.0`؛ متطلب المشروع Node 22 فأحدث؛ GitHub Actions يستخدم Node 22.
- لا Codespace ظاهر في الحساب المتصل عند الفحص؛ لا عملية تشغيل للبوت ظاهرة في مساحة العمل الحالية. لا يثبت ذلك عدم وجود استضافة خارجية.
- لم تُقرأ أسرار تشغيل أو قاعدة إنتاج، ولم تُرسل طلبات إلى Telegram. لا يوجد في هذا الجرد عنوان Webhook حي أو حالة اتصال بعيدة موثقة.
- إعداد التشغيل الحي يتطلب تفعيلًا صريحًا، SQLite موجودة بصلاحيات خاصة، وملف STOP/RUN خاص، وسر Webhook، وعنوان HTTPS. لا يجهز أمر التشغيل هذه الموارد تلقائيًا.

## جرد الأزرار بالأدلة

قورنت أسماء الأقسام الـ16 وأسماء وترتيب الأزرار الفرعية الـ253 بجدول كل قسم في `أزرار_منارتك.md`، دون تعديل التصميم.

- 10 مداخل مرتبطة بشاشات محلية: مجموعاتي، حالة الحماية، سياسات العقوبات والاختبار، السجلات والطوارئ، قائمة المشرفين، سلامة الاشتراكات، FAQ، المكتبة، حالة الرسائل، إعدادات التشغيل.
- 243 مدخلًا يعرض وصف الميزة المعتمدة فقط. هذه الأرقام تخص **الأزرار الفرعية العليا**، ولا تشمل الأزرار المتداخلة أو القوائم القديمة.
- عرض «حالة الحماية» الحالي يفتح مراجعة النتائج المجهولة؛ لا يمثل تنفيذ جميع وظائف حالة الحماية المطلوبة في التصميم.
- الشاشات المرتبطة ليست خدمات مكتملة بالضرورة؛ مثلًا التفويضات محلية ولا تثبت صلاحيات Telegram، والمكتبة قد تكون فارغة.
- توجد إجراءات محلية مؤكدّة داخل بطاقات المجموعات: إيقاف AI، تقييد نطاقي المساعد والنشر، تعليق قاعدة الاشتراك، وإلغاء الاعتماد. ليست عقوبات Telegram.

التفصيل الكامل لكل زر ومساره في `PHASE1_BUTTON_INVENTORY_AR.md` ونسخته الآلية `PHASE1_BUTTON_INVENTORY.json`.

## التحقق القابل لإعادة التشغيل

1. `npm run check`: TypeScript وجميع اختبارات المستودع.
2. أوامر العروض الخمسة الموجودة في package.json: النواة والتعليم وFAQ والنشر والمعاينة/الترحيل؛ كلها محلية.
3. `npm run audit:phase1`: يقارن الوثيقة الرسمية، ويتحقق من صفحات كل قسم والرجوع، ثم يفتح الأزرار الـ253 على JSON وعلى SQLite عبر TelegramUpdateApplication. لكل زر يختبر فتح المالك، منع غير المالك، منع سياق المجموعة، ومنع إعادة تحديث Telegram نفسه. يفحص بقاء بيانات الأعمال دون تغيير، ويسمح فقط بسجلات المعالجة والتدقيق وطابور الردود المعتادة.
4. لإعادة توليد جداول الجرد: `npm run audit:phase1 -- --write`.

كل بيانات الفحص وهمية في مجلدات مؤقتة تُحذف بعد الفحص. يمنع فحص الجرد أي استخدام fetch أو منفذ العضوية، ويؤكد أن عدد الاستدعاءات الشبكية صفر. الفحص لا يثبت العمل على Telegram أو أن كل خدمة خلف زر منفذة.

## الانتقال للمرحلة الثانية

تبدأ المرحلة الثانية من القوائم الحالية؛ لا يعاد B0/B1. تُستكمل المداخل الشفافة والأزرار المتداخلة ومعالجات الوظائف تدريجيًا وفق التفاصيل المعتمدة، مع اختبارات نهاية إلى نهاية محلية، ثم تُستكمل الحماية وخدمات المرحلة الرابعة. تبقى تجربة Telegram مؤجلة ولا تُستخدم نتيجة الجرد لتشغيل BAN/MUTE أو لتغيير STOP تلقائيًا.
