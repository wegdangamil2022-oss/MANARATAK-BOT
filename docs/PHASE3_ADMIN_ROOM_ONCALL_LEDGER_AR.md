# المرحلة الثالثة — 01-04 غرف الإدارة / ADMINLINK-009 — سلامة سجل تنبيهات المناوبة

**تاريخ التعديل:** 8 نوفمبر 2026

## النطاق الموجود
نظام المناوبة الأساسي في `src/admin-room-oncall.ts` يربط البلاغ بمسؤول أول ومناوب بديل بمهلة محددة وموافقة مسبقة، ويُرسل تنبيهات خاصة لا تُنفذ أية عقوبة تلقائيًا. هذا التعديل لا يضيف نظام مناوبة موازيًا أو صلاحية تنفيذ في غرفة الإدارة.

## استكمال سجل الإرسال
أُضيف تدقيق محافظ لسجلات `admin-room:oncall-send:` الدائمة قبل حجز محاولة إرسال جديدة وعند إعادة التحقق من الحجز بعد العمليات غير المتزامنة.

يَرفض المدقق:
- مفاتيح محاولة لا تطابق بنية معرّف البلاغ وبصمة إعداد المناوبة والمرحلة الأولية/البديلة؛
- سجلات مزدوجة للمفتاح نفسه أو نتائج لا يقابلها بدء صحيح؛
- قرارات وأسباب غير متوافقة مع `STARTED` أو نتيجة `CONFIRMED / FAILED_CONFIRMED / UNKNOWN_OUTCOME`؛
- نتائج موقوتة قبل بدء محاولة الحجز، أو بنتيجة تختلف في صاحب المحاولة وإصدار المجموعة؛
- أوقات مستقبلية أو غير صالحة، والسجل الذي يتجاوز حد القراءة المحافظ.

في هذه الحالات **يتوقف إرسال المناوبة الجديد احترازيًا**، ولا تُحذف السجلات أو يُفترض نجاح/فشل Telegram من غير إيصال موثوق. لا يوجد مسار لإعادة إرسال محاولة غامضة. يستمر فحص صلاحية المُناوب ورابط غرفة الإشعارات وصمتها وبوابة السلامة الموجودة قبل الإرسال.

## الحدود
- لا ينفذ تحذيرًا أو حظرًا أو كتمًا.
- لا يكشف نص التقرير أو هوية العضو في رسالة الغرفة.
- لا يُعد السجل المثبت دليلًا على قراءة المشرف أو استلامه؛ الإقرار منفصل.
- **لم تُشغل اختبارات أو بناء أو CI أو Telegram حقيقي** تنفيذًا لتوجيه المالك.
- PR #184 مفتوح وغير مدمج؛ ولا يمس تعديل هذا الملف الفرع #186.
