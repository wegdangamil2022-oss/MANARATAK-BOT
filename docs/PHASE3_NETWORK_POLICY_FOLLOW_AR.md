# المرحلة الثالثة — NETWORK-002: متابعة سياسات الشبكة المشتركة

**حالة النطاق:** كود واختبارات JSON/SQLite دون أي نشر Telegram حقيقي، دون دمج `main`، ودون ادعاء اكتمال المرحلة الثالثة. الملف هنا لتوثيق التطوير على PR #184 بعد فصل الشبكات عن PR #186.

## دخول المالك وتأكيده

- من خاص المالك: «المجموعات والشبكات ← الشبكات والاتحادات ← بطاقة الشبكة ← 📑 سياسات الشبكة المشتركة».
- يعرض البوت مصادر سياسات حماية المجموعات المعتمدة، التي لدى المالك صلاحية إدارتها في الشبكة وإصدارها صحيح. لا تُقبل سياسة `ENFORCE`؛ مصادر `MONITOR/OFF` فقط.
- اختيار مصدر يُنتج **معاينة خاصة** لمجموعات الشبكة المؤهلة، وهي المجموعات بلا سياسة حماية محلية مسبقة. يوضح العدد والأثر؛ لا يوجد تفعيل افتراضي. موافقة المالك مؤقتة (120 ثانية) ولمرة واحدة، ومقيدة ببصمة الشبكة وإصدارات اعتماد المجموعات والحقوق وحالة السياسات والمتابعة. التأكيد القديم أو حساب غير المالك أو ضغط صادر من المجموعة مرفوض.
- ينشئ التأكيد **سياسة محلية لكل مجموعة مستهدفة** بحد أقصى 50 مرجعًا، ويضيف ارتباط متابعة `POLICY` فقط. لا يعيد نسخ استثناءات الأعضاء أو النطاقات المسموحة أو العبارات المسموحة أو الاستثناءات الحساسة. لا تُنفذ عقوبة أو رسالة Telegram بهذه الخطوة.
- زر «⏸️ إدارة المتابعة» يعرض المستهدفات النشطة والمتوقفة. يختار المالك مجموعة واحدة ثم يؤكد إيقاف متابعتها في الخاص بمراجعة النسخة لمرة واحدة. **لا يحذف الإيقاف سياستها ولا يوقف بقية المستهدفات**.

## التحديث والحدود

- تُنفذ المزامنة داخل معاملة حفظ مصدر سياسة الحماية المعتمد نفسه، وليس في عامل مستقل أو عملية Telegram.
- إن تغيّر إصدار الشبكة أو عضوية أحد طرفي الرابط أو تفويض المالك، أو تغيّرت سياسة المستهدف محليًا، أو صارت البيانات/البصمات غير موثوقة، يصبح الرابط `PAUSED` ولا يُستأنف تلقائيًا. التعديل المحلي للمجموعة المستهدفة مقدم على التوريث دائمًا.
- نمط `ENFORCE` لا ينتقل من المصدر أبدًا؛ إذا تغير المصدر إلى سياسة تنفيذية تتوقف المتابعة بدل أن تُمنح صلاحية عقوبة. لا يُنقل إلى المستهدف وصف آخر أو صلاحيات Telegram بسبب عضوية الشبكة.
- البيانات المتوارثة: **قواعد المراقبة المحايدة** وإعداد flood المدعوم فقط، من مصادر صحيحة ومجموعة ذات صلاحية مباشرة. تحفظ نسخة المستهدف وبصمته بعد التحديث؛ إذا لم يتغير المحتوى، لا تُضاعف السجلات.
- استعادة JSON/SQLite ترفض الروابط التالفة أو المكررة أو الحلقات أو تسلسل الوراثة النشط. النوع `GREETING` غير مدعوم في هذا المحرك المنفصل عن المرحلة الرابعة، ومقترحات قوالب الترحيب تحتاج تصميم فصل مستقل دون ربط مصدر المرحلة الثالثة بمحرك الترحيب.

## اختبارات وضوابط القبول

`tests/owner-network-policy-inheritance.test.ts` و`tests/owner-network-policy-ui.test.ts` و`tests/owner-network-inheritance-restore-security.test.ts` على محركَي JSON/SQLite: النقل المرخص، العزل بين المستهدفات، استثناء التعديل المحلي، الإيقاف الصريح، تأكيد مالك لمرة واحدة، تغيّر إصدار الشبكة والمجموعات، واستعادة الروابط ورفض البنية الفاسدة. أي ادعاء عن قبول Telegram الحي منفصل عن هذه الاختبارات.

## ما لا يزال مفتوحًا

- `NETWORK-002` قوالب الترحيب المشتركة وسائر القوالب تحتاج ترابطًا قابلًا للمراجعة مع ملفات المرحلة الرابعة عند دمج الفروع لاحقًا، **ولا يجوز نسخها الآن إلى #186 بلا فصل صحيح**.
- `NETWORK-003` نواة بلاغات الشبكة ومراجعة العقوبات البشرية وفحص الجاهزية للقراءة فقط نُقلت إلى PR #184، دون واجهة مراقبة كاملة ولا تنفيذ حظر أو كتم مشترك.
- لا تعني هذه الشريحة إغلاق `NETWORK-001..007` أو المرحلة الثالثة أو نجاح التشغيل الفعلي على Telegram.


## تحديث برمجي — توريث سياسة إلى مجموعة واحدة (7 نوفمبر 2026)

أضيفت من قائمة مصادر السياسة شبكة الأزرار «📑 كل المؤهلات / 🎯 اختيار مجموعة»، مع عرض معرّفات وجهات المتابعة الجماعية كاملًا قبل التأكيد، وتمكين متابعة مجموعة واحدة فقط بموافقة مستقلة خلال دقيقتين. تنتقل السياسة الجديدة للمجموعة المختارة مع حارس الإصدارات والحقوق وSTOP، ولا تتأثر بقية المجموعات. أصبح محرك الوراثة يرفض نقل قواعد `NAME` و`USERNAME` و`FRAUD` الحساسة عند الإنشاء **وعند المزامنة**، ولا يعتمد شبكة تالفة أو لوحة مالك معطلة. تفاصيل كاملة في `PHASE3_NETWORK_SELECTED_POLICY_FOLLOW_AR.md`.

هذه برمجة فقط بلا اختبارات وبلا Telegram حي تنفيذًا لتوجيه المالك الأخير، ولا تتعارض مع توثيق الفحوص القديمة السابقة.
