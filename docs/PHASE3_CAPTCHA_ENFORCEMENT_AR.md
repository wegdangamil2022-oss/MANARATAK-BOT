# إنفاذ CAPTCHA بموافقة مستقلة

أصبح معالج الانضمام يصل جلسة CAPTCHA بتقييد كتابة العضو الجديد، ثم يصل نجاح التحدي أو القبول البشري بتسوية سبب CAPTCHA عند فتح الخاص. يعمل المسار من خلال ModerationService والبوابة الرسمية، مع إيصالات INTENT وSTARTED والنتائج الموجودة؛ لا يُرسل تقييد من البوابة الاختبارية العامة أو لمجرد تفعيل إعداد التحدي.

## التفعيل والإيقاف

يبقى الإنفاذ متوقفًا على المخازن القديمة. يظهر زر مستقل في محرر المجموعة عند حقن خدمات الإشراف الرسمية: تفعيل إنفاذ CAPTCHA، معاينة، تأكيد مستقل، إلغاء ورجوع. يقرأ التأكيد نوع المجموعة وحق التقييد وحالة STOP، ويعيد فحص الاعتماد والإعدادات والأزرار قبل الحفظ. يرفض المجموعة العادية أو الحقوق المجهولة أو الفاقدة، ويلغي التأكيد إذا تغيّر المصدر أو تنقل المالك أثناء انتظار القراءة. يمكن إيقاف الإنفاذ أثناء STOP دون قراءة إضافية من Telegram.

ترتبط الموافقة بالمجموعة ونسخة اعتمادها وإعداداتها وصلاحية لوحة المالك. تغيير إعدادات CAPTCHA يبطل الموافقة السابقة. الإيقاف يمنع إنشاء القيود وفكها تلقائيًا عبر هذه الموافقة؛ القيود الموجودة تحتاج مراجعة صريحة. لا يرفع تغيير إعداد التحدي أي قيد قائم.

## الانضمام والملكية

يصدر رصد الانضمام إيصالًا مرتبطًا بالعضو والمجموعة والجلسة والتحديث ووقت الحدث ونسخة موافقة الإنفاذ. لا تتحول جلسة اختبار قديمة إلى عقوبة بعد الموافقة، حتى إذا تساوى الطابع الزمني. يتطلب الإنفاذ حدثًا موثوقًا حديثًا وجلسة حالية غير ناجحة، ويُستثنى المالك والمخولون بإدارة المجموعة.

يستخدم السبب مرجعًا ثابتًا للعضو والمجموعة ونسخة الإعداد والاعتماد؛ لا تغيّره إعادة محاولة السؤال. بعد تأكيد التقييد يُحفظ إيصال غرض CAPTCHA مرتبط بمعرّف العملية الأصلية وبصمتها. لا يكفي تشابه اسم سبب يدوي للسماح بفكه. القيود السابقة أو المعلقة أو الغامضة لا تُستبدل، ولا يعاد إرسال محاولة غامضة.

## النجاح والاستعادة

بعد نجاح العضو أو قبوله بشريًا، يعيد فتح الخاص تسوية سبب CAPTCHA المملوك. إذا كان السبب الوحيد، يستخدم مسار الاستعادة الذي يراجع الإيصال والحالة والأذونات وحقوق البوت قبل الفك والقراءة اللاحقة. إذا وُجد سبب مستقل، يستخدم مسار حفظ القيد المستقل؛ لا تزال جميع شروط إثبات السلسلة ونوع العقوبة ومدتها مطلوبة. يُرفض الإيصال المفقود أو المعدل أو مصدر الإعداد المتغير. إذا تأكد القيد وتعذر تثبيت رابط الملكية، يُحفظ سجل إخفاق مرتبط بالعملية للمراجعة ولا يُفك تلقائيًا دون دليل الملكية.

يعرض البوت تنبيهًا إذا اكتملت خطوة CAPTCHA وتعذّر رفع قيدها. يمكن طلب التسوية مجددًا عند فتح الخاص بعد زوال STOP، لكن النتيجة الغامضة تبقى محجوزة دون إعادة إرسال. يحد الاستدعاء إلى ثماني مجموعات للعضو، ويحفظ موضع المتابعة عند وجود مجموعات أكثر حتى لا تحجب حالة غير محسومة بقية المجموعات، بما في ذلك بعد إعادة التشغيل. لا يرسل المسار رسالة خاصة غير مطلوبة. يستمر إثبات نجاح العضو لنفس النسخة بعد تنظيف تفاصيل جلسة قديمة؛ إعادة الانضمام لا تعيد السؤال لمجرد مرور يوم.

## الحدود المتبقية

هذا تقييد قبل النجاح حتى يتحقق العضو أو يُقبل بشريًا؛ انتهاء مهلة السؤال لا يفك القيد تلقائيًا. لم تُستكمل بعد سياسات العقوبات المتدرجة والمؤقت، وتنبيه الانضمام والتنظيف المرتبط به، ودمج الاشتراك وموافقة القوانين في رحلة واحدة. اجتماع CAPTCHA مع قيد سابق يحتاج المراجعة؛ هذه الدفعة لا تطبق CAPTCHA فوق سبب مستقل قائم ولا تلغيه. تغيير الإعدادات أثناء قيد قائم يحتاج مراجعة مستقلة. لا يُعد هذا إغلاق المرحلة الثالثة، ولم يجر تفعيل بيئة Telegram حقيقية أو تعديل قاعدة أصلية.

اجتازت الدفعة قبل الرفع 226 اختبارًا مركزًا، ثم اجتاز اختبارا تسجيل فشل الملكية واختبارا استقلال موافقة المجموعات على JSON وSQLite. يحتاج مصدر هذه الدفعة نتيجة Ubuntu مستقلة؛ لا تُستنتج من قبول المصدر السابق.
