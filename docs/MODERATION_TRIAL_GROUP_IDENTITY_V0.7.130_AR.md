# منارتك v0.7.130 — التحقق من هوية ونوع مجموعة Telegram التجريبية (قراءة فقط)

## الهدف

أصبحت مرحلة جاهزية تجربة الإشراف تتحقق من **هوية المجموعة نفسها**، وليس فقط حقوق البوت وعضوية المستخدم. لا يكفي أن يعيد Telegram حالة العضو وصلاحية البوت في محادثة معيّنة، لأن محادثة من نوع قناة أو هوية مجموعة تغيّرت بسبب الترحيل لا ينبغي أن تُقبل بوصفها مجموعة تدريب عادية.

يضيف الإصدار واجهة `inspectTrialGroupKind` داخل `TelegramBotApiModerationGateway`، ووظيفة `inspectIsolatedModerationGroupReadOnly`، وأمر تشغيل `telegram:moderation-group`.

## ما الذي يفحصه؟

1. اجتياز فحوص SQLite الاحتياطية المتطابقة، ملف `STOP` المحمي، مجموعة واحدة معتمدة وبدون سجل عقوبات أو تفويضات إضافية؛ والحصول على نتيجتين متطابقتين لصلاحية البوت `can_restrict_members`.
2. قراءة `getChat` من Telegram باستخدام معرّف المجموعة المعتمد محليًا. يجب أن تكون `result.id` **رقمًا مطابقًا** لمعرّف المجموعة، وأن يكون `result.type` إما `group` أو `supergroup`. القنوات `channel` والمحادثات `private` مرفوضة. أي استجابة لا تُثبت الهوية/النوع، أو تتضمن `migrated_to_chat_id`، تُعامل كحالة غير موثوقة.
3. إعادة فحص ملف `STOP` وملف قاعدة البيانات والنسخة الاحتياطية وسلامة النطاق بعد كل قراءة بعيدة، ثم إعادة قراءة صلاحية البوت.
4. قراءة نوع المجموعة مرة ثانية مع فحص صلاحية إضافي للبوت. إذا تغيّر نوع المحادثة أو ظهرت استجابة مجهولة بعد سابقة موثوقة، فالحالة `CHANGED` أو `UNKNOWN` ولا تُعتمد المجموعة.
5. التحقق من أصالة دوال القراءة الرسمية بمقارنة مراجع محفوظة عند تحميل وحدة البوابة، بحيث لا يُقبل استبدال دالة `inspectTrialGroupKind` أو تزوير بوابة شبيهة.

كل طلبات Telegram في هذا الفحص **`getChatMember` و`getChat` فقط**. لا يصل مسار الفحص إلى `banChatMember` أو `restrictChatMember` أو أي دالة تعديل.

## أوامر المشغل

هذه أمثلة اصطناعية؛ استبدل المسارات ومعرّف مجموعة الاختبار ببياناتك المحلية، واستخدم مجموعة مخصصة بإذن مالكها. يجب وضع `TELEGRAM_BOT_TOKEN` في بيئة المشغل عبر نظام أسرار آمن، لا في المستودع أو معاملات سطر الأوامر.

```bash
npm run telegram:moderation-group -- \
  --offline-only \
  --state /private/trial/state.sqlite \
  --backup /private/trial/rollback.sqlite \
  --safety /private/trial/telegram.stop \
  --stale-ms 900000 \
  --trial-chat -1001234567890
```

- `PASS` مع `GROUP` أو `SUPERGROUP`: توافق استشاري وقتي للهوية والنطاق والصلاحيات.
- `BLOCKED` مع `NOT_GROUP` أو `UNKNOWN` أو `CHANGED`: لا تُكمل التجربة قبل مراجعة سبب التعارض.
- رمز الخروج `0` يخص `PASS` الاستشاري، `2` يخص `BLOCKED`، `1` يخص الإدخال/التشغيل غير الصالح.

**تغيير مهم في أمر فحص العضو:** أصبحت أداة `telegram:moderation-target` تتأكد تلقائيًا من هوية المجموعة قبل قراءة العضو. لا يختار الأمر مالك البوت كعضو تجريبي، ولا يبدأ اتصال Telegram أصلًا إذا كان العضو المختار هو المالك.

## الحدود

لا يحتفظ تقرير الفحص بعنوان المجموعة أو معرفها أو رمز البوت أو نص الاستجابة أو المسارات الخاصة. ولا يتسبب تشغيل الأمر في تغيير حالة SQLite أو النسخ الاحتياطية أو ملف `STOP`.

النتيجة الإيجابية **لا تثبت** أن المجموعة معزولة فعليًا عن طلاب حقيقيين، ولا توفر إذنًا بتفعيل العقوبات أو رفع `STOP`. لا تزال بوابة العقوبات الحية غير موصولة بالخادم، ويلزم تشغيل فحوص الجاهزية الحقيقية على مجموعة معزولة يديرها المالك قبل تجربة أي إجراء قد يؤثر في عضو.
