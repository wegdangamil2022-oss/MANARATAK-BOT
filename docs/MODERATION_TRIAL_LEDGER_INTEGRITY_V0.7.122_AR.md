# بوت منارتك v0.7.122 — منع جاهزية Telegram عند تلف سجل عقوبة منتهية

## المشكلة الموثقة بالاختبارات

كان فحص `inspectTelegramTrialAcceptanceReadOnly` يكتفي بفحص العمليات غير المنتهية ووجود إيصالات مراجعات مالك يتيمة. ويمكن أن يعرض `PASS` مع تطابق نسخة SQLite الاحتياطية ووجود `STOP` رغم أن سجل العقوبات يضم صفًا منتهيًا تالفًا، أو عمليات مكررة المعرّف، أو تاريخ إنشاء في المستقبل، أو مراجعة مالك مجهولة النتيجة لا يثبتها التدقيق. حارس إرسال العقوبات الحية كان يرفض هذه الأدلة مسبقًا؛ لكن تقرير الجاهزية العام لم يستخدم قاعدة الثقة نفسها.

## المعالجة

- أصبح فحص الجاهزية العام يستدعي `moderationLedgerSafeForDispatch(live, options.now)` على نفس لقطة SQLite المقروءة للعمليات، مع تقييد التاريخ بساعة المراقبة المُدخلة.
- عند وجود تلف بنيوي أو تصادم هوية عمليات أو عقوبات مؤرخة مستقبلًا أو تعارض مراجعة المالك مع تدقيقها، تكون النتيجة `BLOCKED` ويظهر السبب الثابت `UNSAFE_MODERATION_LEDGER`.
- يبقى السبب المخصص `ORPHAN_MODERATION_REVIEW_AUDIT` عند وجود إيصال يتيم بلا عملية أصلية، ولا يُضاف تشخيص عام مكرر للحالة نفسها.
- تظهر `UNRESOLVED_OPERATIONS` بصورة مستقلة عندما توجد عمليات لم تنتهِ، ويمكن أن ترافقها `UNSAFE_MODERATION_LEDGER` إذا كان سجلها أيضًا متعارضًا.
- التاريخ المنتهي السليم، وتدقيق FAQ غير المرتبط بالعقوبات، لا يمنعان الفحص العام وحدهما. فحص المجموعة التجريبية المنعزلة يظل أشد ويمنع أي تاريخ عقوبات سابق.
- لا يتغير سجل العقوبات، ولا نسخة الاحتياط، ولا ملف STOP. لا يتم الاتصال بـ Telegram أو رفع قيد أو إرساله أو إعادة محاولته.
- أسباب الفحص الثابتة لا تتضمن هويات الطلاب والمجموعات، أو بصمات الأدلة، أو مفاتيح التدقيق، أو مسارات الملفات.

## التحقق والتشغيل

تغطي اختبارات SQLite الواقعية سبع حالات: صف منتهٍ تالف مع نسخة مطابقة، عمليتان بنفس الهوية، عملية منتهية في المستقبل، مراجعة مالك بلا تدقيق، تاريخ سليم مع FAQ، إيصال يتيم دون ازدواج تحذير، وسرية مخرجات CLI ورمز الخروج. أُثبتت حالات الفشل أولًا قبل إصلاح الحارس، ثم أُعيد تشغيل اختبارات البناء ومجموعة المشروع عبر GitHub Actions.

عند ظهور `UNSAFE_MODERATION_LEDGER` يجب إيقاف أي خطة تجريبية تعتمد على سلامة السجلات، وفحص المصدر والنسخ الاحتياطية والتاريخ المحلي بواسطة مسؤول مخوّل. لا تحذف صفوف الأدلة لتجاوز المنع، ولا تعتبر `PASS` موافقة على تحويل STOP إلى RUN أو تشغيل عقوبات Telegram الحية.

**الحماية الحية تبقى معطلة افتراضيًا، والنتائج محلية استشارية فقط.**
