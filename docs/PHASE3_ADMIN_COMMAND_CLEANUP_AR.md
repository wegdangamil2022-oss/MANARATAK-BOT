# تنظيف أوامر المشرفين الموثقة — MOD-008 / 09:04

## المسار المستقل عن تنظيف رسائل الخدمة

«لوحة المالك ← 👋 التفاعل والترحيب ← 🧹 الرسائل الخدمية (09:04) ← اختيار المجموعة ← 🧹 تنظيف أوامر المشرفين (موافقة مستقلة)».

يمكن كذلك فتح شاشة تنظيف الأوامر مباشرة عبر زر `ac:1:h` الذي يُعرض في بطاقة إعداد المجموعة. الحذف **متوقف افتراضيًا**، ولا تفعّله الموافقة القديمة لتنظيف رسائل دخول وخروج Telegram.

يختار المالك مجموعة معتمدة، يراجع أثر التشغيل، ثم يؤكد التفعيل خلال دقيقتين بضغطة واحدة غير قابلة للإعادة. يوجد تأكيد مستقل للإيقاف. لا يتغير محتوى الأوامر، أو صلاحيات المشرفين، أو عمل محرك المراجعة والعقوبات.

## ما الذي يمكن حذفه؟

فقط الرسالة الأصلية المكتوبة داخل مجموعة معتمدة، بشروط مشتركة:

1. تحديث Telegram موثوق ببيانات المجموعة ورقم الرسالة وتاريخها، وليس تحويلًا أو تعديلًا أو زرًا شفّافًا.
2. أمر إشراف **معتمد من معالج البوت** يطابق إحدى الصيغ الأساسية: `/ban`، `/mute`، `/warn`، `/unwarn`، `/unban`، `/unmute`، `/kick`، `/review`، `/notice`، `/lock`، `/unlock`، أو إحدى صيغ مساعد قوانين الفقرات المعتمدة: `/warnrule N`، `/muterule N SECONDS`، `/reviewrule N`، `/noticerule N`، `إنذار N`، و`/actrule N`. تُرفض الصيغ الإضافية أو غير المطابقة تمامًا؛ إذا وُجد اسم بوت بعد @ فيلزم أن يطابق البوت الحالي. لا يُعدّ `/delete` أو أي أمر آخر تلقائيًا ضمن هذه المجموعة.
3. المعالج أنهى التحقق من الصلاحيات ونجح في **إعداد معاينة خاصة** للمشرف دون تنفيذ الحكم النهائي، وخرج بالحالة `APPLIED` والسبب المطابق لفئة الأمر: `MODERATION_PREVIEW_ONLY` لأوامر الإشراف وقوانين الفقرات، أو `GROUP_PERMISSIONS_VIEW` للقفل والفتح، أو `RULE_ACTION_CHOICE` لاختيار إجراء فقرة. فتح شاشة اختيار إجراء فقرة ليس تنفيذًا للإجراء، ولا يؤدي التنظيف إلى تنفيذ أي عقوبة.
4. قرار المعاينة `ALLOW` وسجل المهمة الخاصة `ADMIN_SCOPED` محفوظان في المعاملة السابقة، ووجهة المعاينة الخاصة تطابق هوية المشرف.
5. **أكّد Telegram وصول المعاينة الخاصة**: المهمة نفسها انتقلت إلى `SENT` ولها رقم رسالة مؤكد. لا تكفي `QUEUED` أو `SENDING` أو `FAILED_CONFIRMED` أو `UNKNOWN_OUTCOME`. تفحص الآلة السجل بعد أن يمحو المرسل النص الخاص قبل طلب Telegram؛ لا يحفظ المحرك صورة إضافية من رسالة المعاينة.

بعد مرور **120 ثانية** على قبول الأمر، وضمن حد **24 ساعة** من تسجيله، يمكن حذف الرسالة الأصلية إذا بقيت المجموعة معتمدة، وخيار المالك مفعلًا، وصلاحية المشرف المحلية سارية، وحق البوت في `can_delete_messages` مؤكدًا، ومفتاح التشغيل RUN. تُراجع هذه الشروط قبل حجز المحاولة، ثم قبل طلب API.

لا تُحذف رسائل الطلاب، الأوامر العامة `/guide` و`/rules`، الردود النصية غير المعتمدة، الأوامر المرفوضة، أو الردود على بوت آخر. لا يُحذف رد المشرف الخاص ولا عملية عقوبة Telegram. لا يغيّر التنظيف أي قيود على الطالب ولا يمنح المشرف أي صلاحية.

## التدقيق وحدود الأمان

- سجل موافقة مستقل وإصدار وتاريخ قرار. تسجيل هدف الحذف يكون بالمجموعة، المشرف، رقم الرسالة وتحديث Telegram فقط، دون تخزين نص الأمر أو بيانات الطالب المقصود.
- إعادة تحديث Telegram أو استعمال نفس رقم الرسالة لا يضيف مهمتين؛ سقف 20 تسجيلًا للمجموعة في الدقيقة، و5 عمليات حذف لكل دورة افتراضيًا (الحد الأعلى 10).
- يُكتب `STARTED` قبل اتصال Telegram؛ الإرسال الملتبس أو انقطاع الشبكة ينتج `UNKNOWN_OUTCOME` نهائيًا، ولا تعاد المحاولة تلقائيًا بعد إعادة التشغيل.
- إذا سحبت موافقة المالك، أو تغير إصدار المجموعة، أو انحسرت صلاحية المشرف/البوت، لا يُحذف هدف قديم. لا يسعى البوت لتخمين رسائل الأوامر التي لم يستقبل تحديثها.
- المسار يعمل في الوضع الفعلي فقط مع تمكين المرحلة الثالثة، مؤقتاتها ومفتاح تشغيل Telegram. إعداد الخيار في اللوحة **ليس** تشغيلًا حيًا تلقائيًا.

## حدود الإنجاز

هذه الخطوة تغطي **رسائل الأوامر التي أنشأ لها البوت معاينة خاصة موثقة من فئات الإشراف والقفل ومساعد قواعد الفقرات فقط**؛ لا تشمل أمر `/delete` أو أوامر المشرف غير المدعومة ولا كافة فئات رسائل الخدمة في Telegram أو نسخ ما قبل التسجيل. الاستدعاء عبر أمر مساعد للفقرة لا يلغي اشتراط إثبات اعتماد المعاينة وخصوصية استلامها ولا يحذف نص القانون أو رسالة الطالب. تظل تجربة Telegram الحقيقية، المطابقة الشاملة مع الخطة الرئيسية، وقبول المرحلة الثالثة مهام مستقلة. نجاح CI لا يعد تجربة مستخدم فعلية.
