# بوت منارتك v0.7.124 — حجب التكرار المتعارض في سجلات ردود Telegram

## الخلل المثبت باختبارات TDD

بعد استعادة SQLite أو JSON قد يحوي سجل `telegramReplyJobs` سجلين بالمعرّف `updateKey` نفسه، سواء كانا `QUEUED` أو `SENT` أو `FAILED_CONFIRMED`. كان مسار `TelegramReplyDispatcher` يستخدم `find` فيختار أول سجل دون التحقق من تفرد الهوية؛ حتى إن أضيف سجل مكرر أثناء انتظار الاستجابة، أمكن تسجيل `SENT` كأن النتيجة حُسمت بأدلة محلية فريدة.

كما كان فحص الجاهزية العام يكتفي بحالات الردود المعلقة أو غير المحسومة. مع نسخة احتياطية مطابقة وملف STOP سليم كان يعرض `PASS` لسجل ردود نهائي مكرر أو غير صالح بنيويًا.

## التعديل

- قبل بدء فحص العضوية البعيد، لا يعتمد المرسل على صف مكرر بوصفه مدخلًا صالحًا. معاملة حجز الإرسال تفحص عدد الصفوف المطابقة لمفتاح التحديث، وترفض أكثر من واحد بالخطأ الثابت `REPLY_DUPLICATE_UPDATE_KEY` دون إرسال أو حذف النص أو تعديل الحالة.
- بعد عودة نتيجة Telegram، تعيد معاملة حفظ النتيجة التحقق من تفرد المفتاح. إذا ظهر تعارض أثناء انتظار الشبكة، لا يكتب المرسل إيصال `SENT` جديدًا ولا يطمس الأدلة القائمة. قد يكون أثر إرسال واحد قد حدث بالفعل؛ لا يجوز تفسير هذا الرفض بأنه فشل تسليم مؤكد أو إعادة محاولة الطلب.
- أضيفت دالة سلامة محلية نقية `telegramReplyLedgerSafeForTrial` تراجع كل الصفوف الموجودة باستخدام التحقق البنيوي المعتمد `validTelegramReplyJob` وتمنع معرّفات التحديث المكررة.
- أصبح فحص الجاهزية يُظهر `UNSAFE_REPLY_LEDGER` مع الحالة `BLOCKED` عند وجود سجل ردود مكرر أو غير صالح، حتى إذا كانت كلها نهائية. تبقى حالات `QUEUED` و`SENDING` و`UNKNOWN_OUTCOME` معروضة بأسبابها المستقلة.
- لا تتضمن تقارير الحالة أو CLI نصوص الطلاب، أو المفاتيح، أو معرّفات المحادثات أو محاولات الإرسال. لا توجد إعادة محاولة تلقائية أو اتصال Telegram تجريبي في الاختبارات.

## الاختبارات

تغطي الاختبارات الجديدة JSON وSQLite: تكرار المفتاح قبل الإرسال، تعارض صفوف منتهية، والتزامن بعد تنفيذ استدعاء مرسل وهمي. وتغطي SQLite نسخة احتياطية مطابقة تتضمن صفين متعارضين، وصفًا نهائيًا غير صالح، والتوافق مع ردود سليمة مستقلة، ومخرجات CLI المحجوبة والمحدودة دون تعديل للنسخة وSTOP. سُجّل فشل الاختبارات المطلوبة أولًا، ثم يعاد تنفيذها كاملة في CI.

## إرشادات التشغيل

إذا ظهر `UNSAFE_REPLY_LEDGER` فلا تحذف أي سجل ولا تُعد إرسال الردود يدويًا بالاعتماد على هذه الإشارة وحدها. راجع تسلسل نسخ البيانات وسجل التحديثات، مع الفصل بين الدليل المحلي واحتمال وصول رسالة Telegram فعليًا. `PASS` المحلي ليس تصريحًا لتشغيل البوت أو تعطيل STOP.

**الردود الحية الأخرى لا تتغير، وعقوبات الحظر والكتم الحية ما زالت غير مفعلة.**
