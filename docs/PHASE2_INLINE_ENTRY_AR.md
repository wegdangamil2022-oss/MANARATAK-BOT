# المرحلة الثانية — مدخل لوحة المالك الشفافة

هذه شريحة تنفيذية من المرحلة الثانية، وليست إغلاقًا لجميع الأزرار أو وظائف المراحل الثالثة والرابعة.

## السلوك

- `createLiveTelegramServer` يختار `ownerMenuMode: 'inline'` عند إنشاء التطبيق.
- ضغطة زر «🔐 لوحة المالك» الحالي في الخاص تفتح الأقسام الـ16 المعتمدة بالأزرار الشفافة. لم يتغير اسم الزر أو موقعه في القائمة الرئيسية.
- `/ownerinline` يستمر في فتح اللوحة الشفافة، و`/ownerlegacy` يفتح الأدوات القديمة التي لم تُنقل وظائفها بعد. تُذكر الأوامر في رسالة البداية للمالك فقط.
- المنع الخادمي للهوية وسياق الخاص يبقى قائمًا؛ معرفة الأمر ليست تفويضًا.
- التكاملات التي تنشئ `TelegramUpdateApplication` مباشرة تحتفظ بالسلوك القديم ما لم تختَر `ownerMenuMode: 'inline'` صراحةً. هذا يتيح نقل كل تكامل بعد اختباره.
- callbacks والتنقل والرجوع تستخدم معالجها الحالي وoutbox؛ لا يفعّل هذا التغيير أي عقوبة أو حملة أو ربط API أو AI.

## الإثبات المحلي

اختبارات JSON وSQLite تفتح الزر الحالي في الوضع الشفاف وتثبت صحة InlineKeyboard، ووصول المالك لأدواته القديمة، ومنع غير المالك من الأمرين والزر. اختبار HTTP محلي ينشئ خادم التشغيل الفعلي مع SQLite وملف RUN وهميين ثم يرسل تحديثين موثقين بالسر التجريبي، ويتحقق من وصول inline ثم ReplyKeyboard إلى منفذ الإرسال الوهمي. لا يتصل الاختبار بـTelegram.

تستمر متابعة الأزرار غير المنقولة وفق جرد `PHASE1_BUTTON_INVENTORY_AR.md`. وجود مدخل شفاف لا يغيّر حالة الأزرار الـ243 المصنفة DESIGN_ONLY حتى تُنفذ وظائفها وتُختبر.
