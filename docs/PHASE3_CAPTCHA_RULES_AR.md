# موافقة قوانين المجموعة ضمن تحقق CAPTCHA

يمكن للمالك تفعيل طلب الموافقة من إعداد CAPTCHA بعد نشر قوانين المجموعة واعتماد نطاقي التصفح والتحقق. تعرض الواجهة معاينة مستقلة وتأكيدًا وإلغاءً؛ لا يؤدي تفعيل طلب الموافقة وحده إلى تقييد عضو. إذا لم يُفعّل إنفاذ CAPTCHA، يظل التحدي والموافقة خطوتين محليتين دون منع كتابة.

بعد نجاح العضو في CAPTCHA أو قبوله بشريًا، تظهر له الفقرات الفعالة من إصدار القوانين الحالي في الخاص وزر الموافقة. الزر خاص بصاحبه ومحدود الوقت، ويُفحص انتماء العضو للمجموعة ومصدر القوانين قبل العرض والقبول. الرجوع إلى الرئيسية يلغي الزر السابق، وفتح البوت مجددًا يعرض الموافقة المعلقة. تُوزّع الحالات المعلقة على دفعات حتى لا تحجب مجموعة غير متاحة المجموعات الأخرى.

يبقى قيد CAPTCHA المملوك للبوت حتى موافقة العضو عند تفعيل الإنفاذ واشتراط القوانين. يرتبط دليل الموافقة بالعضو والمجموعة وإصدار القوانين واعتماد المجموعة وسياسة الموافقة ومرجع التحدي. تعديل القوانين يتطلب موافقة الإصدار الجديد. تغير الإعداد أو الدليل أثناء فحص فك القيد يمنع استعمال الفحص القديم؛ تبقى الأسباب المستقلة خاضعة لمساراتها. تُعاد مراجعة العضوية والإصدار والزر عند إرسال شاشة القوانين من الطابور، ولا تسجل موافقة بمجرد العرض.

الربط الحالي يغطي CAPTCHA والقوانين دون شرط اشتراك فعّال. حاجز الاشتراك المؤقت ما زال يمنع تفعيل إنفاذ CAPTCHA أو تسويته مع شرط قناة فعّال إلى أن تكتمل الرحلة المشتركة وحماية القيود السابقة. كذلك لا تنجز هذه الشريحة التدرج العقابي أو إشعار الانضمام وتنظيفه. تجربة Telegram الفعلية مؤجلة بطلب المالك، ولا تعد هذه الوثيقة إغلاقًا للمرحلة الثالثة.

اجتاز البناء و115 اختبارًا مركزًا تشمل إعداد المالك، وموافقة العضو وتغيير القانون والعضوية أثناء الفحص، وفك القيد، والتسليم المعلق، والرجوع، وإعادة التشغيل على JSON وSQLite. سجل الفحص المحلي: `artifacts/section-closure/captcha-rules-accepted-focused.log`. اجتازت 101 حالة إضافية لمسارات الاشتراك والردود والتنقل قبل التدقيق الأخير. يلزم فحص Ubuntu للمصدر الجديد بصورة مستقلة.
